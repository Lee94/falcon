# 目标：宿主机节点统一管理项目与会话，并支持客户端升级服务端

## 背景
A、C 分别通过 SSH 连接 B 时，项目与新终端会话均由 B 的 Falcon 节点及数据库管理。客户端可直连节点，也可经本机服务转发。当前项目清单同步只作为迁移输入。

## 已确认范围
- workspace 指项目；窗口布局继续按客户端保存。
- 保留现有项目及全部项目属性、附属关系和工作目录；旧 terminal 不要求迁移，不擅自结束仍在运行的旧任务。
- 桌面与 Android 均可检查并升级当前服务端及所连接的 SSH 节点。
- Tailscale 设备行单行显示名称、操作系统、在线状态、已添加标记和添加按钮；隐藏地址、DNS 和所属用户，名称不足时省略。

## 流程
1. 定义稳定节点身份与资源路由，建立 SSH 上的节点部署、复用、连接。
2. 项目及会话操作转交所属节点，文件与 Git 跟随项目归属，持久会话由宿主机 sessiond 持有。
3. 备份并幂等迁移旧项目，冲突报告且保留原始数据，停止双向清单同步。
4. 发布独立服务端产物与校验文件，增加升级任务、独立帮手、健康确认与写入开放前的回滚。
5. 接入桌面与 Android 升级入口，调整 Tailscale 列表。
6. 运行相关局部检查与隔离多节点集成验证，修复发现的问题，更新架构与使用说明。

## 验收标准
- [x] A 在 B 创建项目和会话，C 连接 B 可见并可打开相同会话。
- [x] A 断线不结束 B 的持久会话，多观看端保持现有尺寸仲裁与回放语义。
- [x] 重试不重复创建资源；节点不可达有明确结果。
- [x] 项目及附属关系迁移完整且幂等，项目目录不受影响。
- [x] 客户端可检查、发起及查询服务端升级，按目标平台下载并验证发布产物。
- [x] 升级保留节点身份、实际启动配置、项目和新架构持久会话；失败可恢复且不覆盖已接受的新写入。
- [x] Tailscale 设备行仅显示约定字段且不换行，搜索与预填功能正常。
- [x] 相关局部测试通过，真实运行环境未被测试修改。
