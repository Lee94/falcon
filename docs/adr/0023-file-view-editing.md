# 文件窗口：在源码视图里直接改、保存写回

文件窗口原先只读（ADR 0007 的查看 tab 搬进列式工作区之后也一样），理由同 ADR 0009 当初没做改目录："改文件是终端里的事，这里不做半个编辑器"。用下来，"看到一处错字 / 改一个配置值"这种两三行的改动，为它开终端、找路径、起 vim 太绕，而文件窗口已经握着内容、源码视图本身就是 gpui-component 的代码编辑器（只是设了只读）。

现在：能原样写回的文本在源码视图里可以直接改，⌘S（其它平台 Ctrl+S）或工具栏的保存按钮写回去。分量仍是"顺手改两行"：没有自动保存、没有 LSP、没有多文件，大改还是终端里的编辑器。

## 决定一：只有能原样写回的文本才能编辑

`GET …/file` 的文本预览加了 `version`（字节的 sha256），只在这两条都成立时给：没有被 2MB 的查看上限截断、本来就是合法 UTF-8。截断的存回去丢后半截；不是 UTF-8 的（GBK、Latin-1）显示的是替换过 U+FFFD 的文本，存回去会把原字节改成 `EF BF BD`。没有 `version` 的照旧只读（不是 UTF-8 的在工具栏上说一句）；老服务端不给这个字段，新客户端连上去自然退回只读。

图片、二进制、超大文件不在讨论范围。

## 决定二：写回 = `PUT …/file?path=&base=`，按内容版本判冲突

请求体是要写进去的原始字节（octet-stream），整份收进内存（上限 16MB，给"打开之后又粘进去一大段"留余量）。`base` 是查看时拿到的 `version`：服务端先读一遍现在的内容比哈希，对不上回 409"文件在打开之后被改动过"，文件没了回 409"文件已被删除或移走"。前端弹框问要不要覆盖，覆盖 = 不带 `base` 重发。不覆盖就什么也不做——修改还在编辑器里，复制走之后刷新看别人改成了什么。

用内容哈希不用 mtime：远端读命令本来就把字节带回来了，不必为 mtime 再改四种环境的读脚本；mtime 的精度（FAT / 部分网络盘是 2 秒）与"git checkout 回同一份内容"也都不成问题。比对与写入之间隔一次往返，不是原子的比较并交换——它挡的是"窗口开着的这几分钟里终端里的编辑器 / git / agent 改了文件"，不是同一毫秒的并发写。

## 决定三：原地覆盖，不"临时文件改名到位"

ADR 0008 的上传是临时文件收满再 `mv` 到位；写回不能照搬：改名换掉的是 inode，权限位（脚本的 +x）、属主、硬链接一并丢失，符号链接被换成普通文件。编辑一个文件不该改这些。

- 本机：内容整份在内存里，`truncate + write_all` 一次写完。
- 远端 POSIX：stdin 先收进 `mktemp` 的临时文件（放 `$TMPDIR`：目标目录不一定可写，中途断了也不在工作目录里留垃圾），比字节数，够了再 `cat 临时文件 > 目标`。先收满的理由同 0008：通道中途断开时 `cat` 照样退 0。覆盖那一步在宿主机本地，不经网络。
- 远端 Windows：base64 行（同 0008）攒进 MemoryStream，比字节数，再以 `FileMode.Truncate` 打开目标写入。不用 `Create`（CREATE_ALWAYS 清隐藏 / 系统属性，碰上隐藏文件直接拒绝）。

目标不存在时新建（覆盖一个已被删掉的文件 = 把它写回来），上级目录不在报"路径不存在"。

## 决定四：换行与末尾换行跟原文件走

编辑器显示时吞掉末尾那个换行（不吞多一个幽灵空行），回车只插 `\n`。存回去时还原（falcon-core 的 `file_text`）：原文件**全是** CRLF 的，新敲的 `\n` 也写成 `\r\n`；混合的、全 LF 的不去"纠正"；原来以换行结尾就补回同一种换行，没有就不加。末尾有没有换行因此在编辑器里改不了（与 vim 的 fixeol 同一个取舍），换来"只改了一个字，diff 就只有一个字"。

## 决定五：有没存的修改时，离开之前先问

编辑器常驻在 FileView 上：切到预览不扔（Markdown 预览照着没存的内容渲染；HTML 预览加载的是磁盘上的字节，工具栏上说"预览的是已保存的内容"）。会把它扔掉的出口都拦：

- 换文件（文件窗口是预览语义，点别的文件就地换内容）、关文件窗口、刷新：拦在 `Workspace::open_file` / `close_file` 上，FileView 把脏标记写到工作区的 `file_dirty`；
- 关整个窗口：`on_window_should_close`；⌘Q / 菜单退出：Quit 动作推迟到这一轮分派之后去找有修改的窗口（分派当中那扇窗口被借出去，读不到它）；
- 浏览器版：有修改时挂 `beforeunload`（`Platform::set_unsaved_changes`），关标签页 / 刷新由浏览器自己问。

不拦的：文件面板里把这个文件删了（删之前已经确认过，文件也没了）；Dock 上的退出与关机（走系统那条路，拦不住）。文件面板里把它改了名：窗口跟到新路径上，修改留着、版本照旧，保存写到新路径。

## 已知取舍

- 没有"外面改了就提示"：文件窗口不轮询（ADR 0007 的理由仍成立），冲突要到保存时才知道。
- 改名时语言高亮不跟着换（编辑器留着就是为了不丢修改）；存一次、刷新就对了。
- Windows 远端的写回脚本只有命令串的单测，未在真机上验过；POSIX 远端脚本在单测里经本机 sh 真跑（权限位、符号链接、冲突、删除后写回）。
