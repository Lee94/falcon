# 浮动岛骨架：窗口底 + 圆角面板、统一圆角阶梯、主题着色的选中态

在这之前，界面是 shadcn 的默认长相：纯白（或纯黑）铺满，侧栏 / 主区 / 右面板之间靠 1px 边框分栏，tab 是切进条里的方格子（选中态顶一条 2px 实线），列表的 hover 与选中是贴着容器边缘铺满整行的方块，圆角一律 8px。功能都对，但它读起来像一个还没做视觉的管理后台——所有分隔都是线，所有形状都是直角方块，颜色只有灰阶。

现在照 Firefox 2026 的 Nova 重设计做一次整体视觉调整。Nova 能落到这个产品上的，是三件具体的事：**分段的浮动岛**（标签与地址栏浮在窗口底上，网页内容被框进一个圆角容器里，而不是顶到窗口边）、**统一的大圆角**（岛、菜单、按钮、hover 块共用一套曲率）、**更暖的配色与少量的色彩亮点**（Nova 用的是 Firefox 的品牌暖色）。

决定：

1. **桌面骨架是浮动岛**。最外层铺 `--app`（窗口底），侧栏 / 主区内容 / 右面板都是浮在它上面的圆角面板（`.island`），彼此只隔 6px 一道缝——**分栏边框整条删掉**。右侧活动栏不成岛，图标直接落在窗口底上。
2. **tab 是胶囊，不是格子**。选中的那颗直接用 `.island`，和它下面那座内容岛同色同曲率；tab 条自己没有底色，浮在窗口底上。
3. **一套圆角阶梯**：`--radius` 从 8px 提到 12px，控件从它减出来（sm 8 / md 10 / lg 12 / xl 16）。岛、对话框、菜单、按钮、列表 hover 块全部落在这套阶梯上。
4. **窗口底只压亮度、不动色度**（`shiftLightness`）。主题的色调——Solarized 的暖米、Catppuccin 的紫灰、Nord 的蓝灰——留在整屏最大的那块颜色上。这是 Nova 的"更暖"在这个产品里唯一诚实的翻译：Falcon 的品牌色就是用户选的那套主题。
5. **选中态改用主题自己的 ANSI 蓝着色**（`--tint`）。侧栏当前项目、活动的面板按钮、命令面板的当前项、分支树的当前分支——从灰块换成弱蓝块。这是 Nova 的 "pops of colour"，但只给"当前选中"，不当装饰底。

## Considered Options

- **只把圆角调大、颜色不动**：一天能做完，但 Nova 的观感八成来自"岛浮在底上"这件事，光调圆角只会得到一个圆角版的管理后台。
- **岛和岛之间用不同底色（侧栏更暗、主区更亮）**：VS Code 那套。并排的岛有色差看着像没对齐，而且终端岛的底色**必须**精确等于主题底色（差一点点，圆角边缘就露出一圈色差）。最后是所有岛同色，唯一的层次交给 `--app`。
- **窗口底往黑掺（`mix(bg, #000, t)`）**：最直觉的压暗。但 OKLab 里往黑掺会同时拉低 a/b，压两下 Solarized 的暖白就成了中性灰——463 套主题的性格全被洗到同一个灰上。改成只减 L。
- **窗口底往前景色掺**：色调倒是保住了，但浅色主题的字色多半是近黑，结果与往黑掺差不多；深色主题反而会把底色往字色的色相上拽。
- **给界面引入一个固定的暖色强调色（Nova 的火焰橙）**：那是 Firefox 的品牌色。写死一个色相，等于让 463 套主题里一大半在自己的配色上顶着一块外来的橙。
- **内容区的圆角容器由 App.tsx 统一提供**：单列终端时最省事，但多列终端画布（一列一个会话）就会变成"大岛里套小岛"的双层框。改成**每个内容视图自己是岛**：终端画布的每一列、总览、差异、文件预览各自 `.island`。
- **列表行一律改成内缩的圆角块**：Git 提交图那条列表不行——图形的泳道线要在行与行之间连起来，行内缩会把线切断。那条列表保留通栏底色，只把颜色换成 `--tint`。

## 实现要点

- **`.island` / `.sunken` 是两个 `@layer components` 里的类**（`styles.css`），不是 Tailwind utility 的堆叠：它们在十几个地方复用，而且"浮起"与"凹陷"是这套视觉的两个词，值得有名字。`.island` 的描边用 `box-shadow` 的 0 偏移环而不是 `border`：省掉 border-box 的 1px 尺寸账，也不会在 `overflow-hidden` 的容器里被内容压掉。**投影只对浅色主题有用**（深色里投影是黑的，落在更黑的窗口底上等于没画），深色的边缘全靠 `--app-border` 那圈提亮描边，所以两者都给。
- **`--app` 的两个方向**：底色还压得动就压（浅色 −0.05 L，深色 −0.07 L）；压不动的近纯黑主题（`#000`、`#0a0a0a` 那批，OKLab 亮度 ≤ 0.16）反过来提亮到 L≈0.21，凹陷感换成浮起感，圆角一样看得见。阈值与两个方向都在 `derive.ts`，全部 463 套主题的"窗口底与面板底至少差 0.045 L"有测试钉住。
- **`shiftLightness` 要做色域收缩**：高饱和的底色（Borland 的 `#0000a4`）在 OKLab 里降 L、保 a/b 会掉出 sRGB，直接截断分量就等于**没压够亮度**（实测只降了 0.033，肉眼分不出）。二分把色度收到刚好回色域里，亮度优先保住——层次是靠亮度差看出来的，代价是一点饱和度。这个 bug 是测试先发现的，不是眼睛。
- **首帧不跳色**：`index.html` 的内联脚本仍然只写 `--background`，窗口底用**相对颜色语法**在 CSS 里算 —— `oklab(from var(--background) calc(l - 0.05) a b)`，与 `derive.ts` 同一个算法。前面留一行 `color-mix()` 兜底给不认相对颜色语法的浏览器（认的会被后一行覆盖）。近纯黑的主题 derive 会改成提亮，那一帧的差是黑对黑。
- **拖拽把手挪到缝里**：`ResizableSlot` 的把手原本压在分栏边框上（`-right-[3px]`），现在正好盖住两座岛之间的 6px 缝（`-right-1.5`），拖的是缝而不是岛的边缘。
- **终端的四角归岛裁**：xterm / rio 的 canvas 本身是方的，圆角由 `.island` + `overflow-hidden` 裁。终端已有的 `pl-2 py-1.5` 内边距（8px / 6px）大于 12px 圆角在那个高度上的内缩量（≈1.6px），字符不会被切。终端底色就是 `--background`，与岛同色，圆角边缘没有色差。
- **多列画布的活动列用 `outline` 不用 `ring`**：`.island` 的描边是 `box-shadow`，Tailwind 的 `ring-*` 会把整条 box-shadow 替换掉，描边和投影一起没。`outline` 与 box-shadow 互不干扰，而且跟随 border-radius。
- **`shadow-*` 与 `ring-*` 同坑，拖拽中的 tab 用 `.island-lifted`**：拖起来的那颗原本加 `shadow-md`，而 utilities 层的 box-shadow 会把 `.island` 那条整个替换掉——拖动中的选中 tab 只剩一块没边的白（深色里更明显，描边正是深色唯一的边缘）。`.island-lifted` 把描边和抬高一档的投影写在同一条 box-shadow 里；没选中的 tab 本来就没描边，继续用 `shadow-md`。
- **画布要给岛留 1px 呼吸位**（`-inset-px` + `p-px`）：列是 `h-full` 顶满的，而画布是滚动容器（`overflow-x-auto` 一设，两根轴都成了裁剪盒），`outline` 和 `.island` 的 box-shadow 都画在 border box 外沿，于是贴着画布边的那几条全被裁掉——实测活动列那圈蓝框只剩左边一条竖线，上下右三边连同岛自己的描边一起没。往外扩 1px 再往里收 1px，列的尺寸与位置分毫不动。`--term-canvas-w/h`（后台列的几何）用的是 `clientWidth/Height`，含 padding，要把这 1px 扣掉，否则后台列比前台列宽 2px。
- **分段控件是"凹槽里浮起一块"**（`Segmented`、`ThemeChoice`）：槽用 `.sunken`，选中项直接用 `.island`。同一套材质换个尺度，Nova 的 segmented 在微观上就是这个形状——顺带把原来"选中项铺黑底"的高对比块换掉了。
- **lucide 笔画降到 1.75**（`svg.lucide`）：默认 2px 在 13px 的界面里偏硬，配不上这套曲率。Nova 也把图标重画得更圆。给了 `size-*` 的图标不受影响。
- **毛玻璃只给真正浮在内容之上的层**：菜单 / 下拉 / Select / 命令面板 / 对话框 / 移动端抽屉 / toast 的底降到 80–90% 不透明，配 `backdrop-blur-xl`（浮层）或 `2xl`（对话框）。岛不加——岛下面只有纯色窗口底，模糊没有东西可模糊，只会把字变淡。**遮罩层也不加**：第一版给 `DialogOverlay` 上了 2px 背板模糊，结果整屏（侧栏、终端画面）全糊成一片，既盖掉了用户正在看的东西，铺满视口的 `backdrop-filter` 开销也不小；改回纯暗化，糊的只是浮层自己那块。设置对话框的左栏跟着降到 `bg-app/60`，否则实色的槽压在半透明的对话框上会分成两种材质。
- **焦点是一条 1px 边框，不是一圈光**：shadcn 默认的 `ring-[3px] ring-ring/50` 在这套视觉里太吵——半透明的粗光晕糊在圆角上，边缘是虚的。全站 28 处换成 `ring-1 ring-ring`（实色），`aria-invalid` 的 destructive 环同理。多列终端画布的活动列也从 `outline-2 outline-tint-strong/45` 换成 1px 实色。同一条规则：**状态用实色细边框或着色面表达，不要用半透明的粗环**——Git 的 reset 模式选项因此从 `border-primary bg-primary/5` 改成 `bg-tint`。
- **这些地方刻意没改**：面板顶部工具区与内容之间的 `border-b`（那是功能分区，不是分栏）；密集列表里的行分隔线（飞书待办、端口转发这类多行条目，去掉线会糊成一片）；Git 提交图的通栏选中态；移动壳（全屏终端不做浮动岛，`MobileShell` 自己盖满）。
- **`--sidebar` 这组 token 的值没动**，改的是组件：侧栏与右面板的容器从 `bg-sidebar` 换成 `.island`（即 `--background`）。设置对话框的左栏、移动壳顶栏仍用旧层次，它们不在浮动岛的语境里。

## 验证状态

- 无头 Chrome 截图走查：浅色 / 深色下的总览、终端、文件面板、Git 面板、修改面板、设置对话框、命令面板、右键菜单、移动壳（390×844）各一轮；毛玻璃与焦点边框在有内容的背景（总览的表格）上另走一轮。
- `pnpm --filter @falcon/web typecheck` 与全仓单测（364 项，新增 4 项：`shiftLightness` 的只动亮度 / 色域收缩 / 与往黑掺的对照，`--app` 在全部 463 套主题上的亮度差与暖色主题的色度保留）。
- **没验的**：Safari / Firefox 下的相对颜色语法回退路径（Chrome 已验）；圆角裁剪与 `backdrop-filter` 对 WebGPU 渲染器合成性能的影响（只在真机上量得出来）；真实 SSH 远端与 Windows 远端的会话在新骨架下的表现（视觉无关，但没跑过）。
