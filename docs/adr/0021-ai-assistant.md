# AI 助手：一段对话 = 一个终端 + 一段 AI 上下文，内置 agent 把命令打进那个终端，本地 agent 走 ACP

状态：**已实施**（2026-10-15）。做法与验证记录见 [docs/design/ai-assistant.md](../design/ai-assistant.md)。没在真实的 Claude API 与真实的 ACP 适配器上跑过，只对按协议写的替身跑过；SSH Host 上的对话、浏览器版里的交互都没验证。

侧栏「设置」旁边加一个入口，打开一个浮在主区左下角的面板。面板里是一段段对话，一段对话是某台机器上的一个终端加一段 AI 上下文（像 Warp 的一个标签）：你在终端里敲命令，跑完的命令记成时间线上的命令块；⌘⇧I 切到 Agent 输入，把任务交给 AI。AI 可以是 falcon 内置的 agent（直连 Claude API），也可以是经 ACP（Agent Client Protocol）接进来的本地 agent（Claude Code / Codex / Gemini CLI……）。

## 决定一：对话的终端按机器挂，不属于项目

「机器」= falcon 后端本机，或一台已保存的 SSH Host（与「中转」同一个口径，ADR 0016）。对话的终端就是 `sessions` 表里的普通会话，owner 换成合成 id：`machine:local` / `machine:host:<id>`；一台机器上一段对话一个，对话记着自己的会话 id。持久性、接回、Detach / Terminate 全部照旧：收起面板只是 Detach，删对话才 Terminate。会话路径上取 owner 一律走 `owner_row`，`GET /api/sessions` 按前缀滤掉它们——侧栏、总览、命令面板都看不见。

不加列：前缀本身就是标记，加一列只是多一处要保持一致的东西。不复用中转的主机链路（`host:<id>`）：那条链路断线只重连中转，会话要的是「重连并接回」，两套语义。

## 决定二：一条时间线，终端只露出当前提示符；AI 的东西不往终端网格里画

时间线从上往下是命令块、你的话、AI 的话与工具卡片，最底下是这段对话的终端——外面一层只露出「当前提示符到光标」那几行（全屏程序开着、输出多过一屏时整块露出来）。跑完的命令由服务端从 shell integration 的标记里切出来，记成命令块接到时间线上。

没选「把 AI 的话插进终端网格」：终端网格是守护进程维护的 VT 状态，往里插不是 PTY 来的内容，会和 shell 的提示符重画打架，接回时也还原不出来。Warp 的「块」是它自己的终端模拟器画的；我们的命令块是另一份东西（服务端存的原始输出，客户端按终端习惯处理 `\r` 与颜色，不做列宽折行），终端本身一个字节不改。

## 决定三：内置 agent 的命令打进对话的终端，agent 看得见你敲过什么

agent 与你共用同一个 shell：激活的 venv、export 的变量、`cd` 过的目录都在，你在实时区域里看得到 agent 在跑什么；反过来，每句话发出去时，上一句之后你在终端里敲过的命令（命令行、目录、退出码、输出）自动随这句话带上。

为此只给对话的终端注入 shell integration（zsh / bash / fish 的 OSC 133 + OSC 7 + VS Code 的 633;E 命令行），服务端在输出流上认标记，知道 shell 是否停在提示符、一条命令的命令行与输出从哪到哪、退出码多少。超时不杀命令（你看得见、停得了），停止 = Ctrl-C。认不出的 shell 与 Windows 宿主机不注入，没有命令块，agent 的命令退成独立进程。

没选「每条命令一个独立进程」作为主路径：它更稳（并行、超时可杀、不怕 vim 占着前台），但 agent 与你各在各的环境里。代价是这套注入与「等 shell 空闲」：前台被 TUI 占着时 agent 只能等，最多 60 秒。

项目里的普通会话不注入：那是用户的地盘，falcon 不往里塞钩子。

## 决定四：agent 在服务端跑，两种 agent 抹平成一种条目流

- 收起面板、断网、换设备都不打断在跑的一轮；浏览器版起不了子进程，也不该拿到 API key；
- 条目照 ACP `session/update` 的形状定义在 falcon-proto（自己的类型，不引 ACP 的 crate：它一周三个大版本，客户端协议要稳、要编进 wasm），命令块是 falcon 自己加的一种。内置 agent 直接产出，ACP 的更新在服务端映射一次。界面只认这一种；
- 客户端连上 WS 先收快照再收增量（同终端的「先回放再接实时流」），断线期间发的话排队、连上再发。

## 决定五：内置 agent 用 Claude Messages API，四个专用工具

`run_command`、`read_file`、`write_file`、`edit_file`。文件操作做成专用工具而不是让模型 `cat` / `sed`：卡片能画 diff，审批能分开（读不问，写要问）。默认模型 `claude-opus-5-5`，自适应思考 + 显式的思考强度；`eager_input_streaming` 与自动换模型（`fallbacks`）只在官方地址上开——网关可能不认。API key 用 `SecretBox` 加密存服务端，永不下发。

没做别家模型的直连：要用别家模型就走 ACP（Codex、Gemini、OpenCode 都讲 ACP），falcon 不维护第二套 API 客户端。

## 决定六：ACP agent 只在本机起，客户端自己写

- 只在本机：Claude / Codex 的 ACP 适配器在自己的进程里跑命令、改文件，不走客户端的 `terminal/*` / `fs/*`，agent 在哪台机器上就只看得到哪台，它的命令也不进对话的终端。SSH Host 上的对话只能选内置 agent；在远端用 Claude Code 照旧开 agent 会话（ADR 0013）。没选「经 SSH exec 在远端起 agent」：要远端自己装 Node 与各家 agent、处理远端的登录态，收益不抵复杂度；
- 自己写 JSON-RPC：`agent-client-protocol` 3.x 的处理器要求 `Send`，跟引擎线程的 `Rc` / `RefCell` 合不来；收发循环本身几十行。字段按 JSON 宽松地读；
- 声明 Zed 的终端输出扩展（`_meta.terminal_output_delta`）：Claude / Codex 靠它把命令输出流给客户端，卡片才有实时输出。

## 决定七：面板不是模态对话框，浮在主区左下角

入口在侧栏左下角，面板就从那里贴着侧栏弹出；开着时照样能点画布里的终端、用工作区的快捷键。它压在终端上面，两者同一个底色，所以破例带一圈细边与阴影（岛的规矩是只靠底色分块，ADR 0011）。

## 后果

- 会话路径上新增的每一处取 owner 的地方都要走 `owner_row`；直接 `db.get_project` 会把对话的终端当成「项目不存在」；
- 注入脚本要随 shell 的版本差异维护（bash 3.2 的 DEBUG trap 与 `history 1`、bash 5.1 的数组 PROMPT_COMMAND、zsh 的 ZDOTDIR 还原），改动先跑 `shell_integration` 的真 PTY 测试；
- 命令块是服务端从输出流里切的，shell 打在 `D` 之前的东西都会混进来：zsh 的 PROMPT_SP 已经认出来去掉，别的主题 / 插件在 precmd 之前打的字照样会进块；
- 实时区域靠「提示符的绝对行」定位，客户端改尺寸时按光标还原；shell 自己在 SIGWINCH 时重画提示符而不重打 `A` 的情况下，露出的那几行可能差一两行，等下一个提示符校准；
- 你在对话终端里敲的东西会随下一句话发给模型；
- 一段 ACP 对话一个进程，没有空闲回收，删对话、换 agent 或服务端退出时收掉。

## 后记：同一天从「弹窗 + 两页」改成现在这样

第一版（同日上午）是一个模态弹窗：每台机器**一个**助手终端（Shell 页），Agent 页是对话列表，对话与终端是两样东西；agent 要知道你干了什么，得在发送时勾「附带终端最近输出」（取屏幕最后 80 行）。用下来的问题：

- 对话与终端分开，一台机器上几段对话共用一个 shell，「这段对话里 agent 改了什么目录」说不清；
- 屏幕最后 80 行是一团字，没有命令行、退出码，一屏装不下的输出就丢了；
- 弹窗太大、模态，开着时整个工作区用不了。

改成 Warp 的模型：一段对话就是一个终端，切 Shell / Agent 只是换输入方式，同一条时间线；为此加了 633;E（命令行）与服务端的命令块，去掉了勾选框与 `TermCore::recent_text`。弹窗换成非模态的小面板，⌘J 不用再在弹窗里另接一份。

同日第三轮（照用户给的参考图）：Agent 的输入不再是底部一个独立的输入框，而是时间线最底下那一行「命令行」（`✦ 目录 ▌`），与 Shell 的提示符同一个位置；你说的话也画成 `目录 ✦ 这句话`。AI 的一轮收在一道竖线里，思考直接画出来（不再折成一行「思考」），每一步上面有一句 `description`（内置 agent 的 run_command 必带），卡片只画命令与状态、等批准时是一句问话加「执行 ⌘↵ / 总是允许 / 修改 / 拒绝」；agent 跑完的输出记成卡片后面的命令块（`byAgent`），画得和终端里一样。「修改」让人在卡片上改了命令再跑，服务端会告诉模型实际跑的是哪条。批准从 ⌘Y 换成 ⌘↵（按钮上标着）。
