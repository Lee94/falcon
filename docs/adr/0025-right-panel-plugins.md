# 右侧栏插件：后端跑命令、客户端画声明式面板，内置第一个是系统监控

右侧栏的四格（文件 / 修改 / 历史 / 飞书项目）都是写死在客户端里的。想在旁边多放一块"自己关心的东西"——这台机器的负载、某个服务的状态、项目里的 TODO、CI 跑到哪了——只能改 falcon 的源码。现在右侧栏的内置四格之后可以挂**插件**：一个插件一格，面板内容由插件给，falcon 只负责跑它、画它。内置了三个：「系统监控」「Docker」与「Agent 用量」。

插件作者手册（协议全文、环境变量、例子）在 [`docs/plugins.md`](../plugins.md)，例子在 `docs/plugins/examples/`。

## 决定一：插件不往客户端里塞代码，只交一份声明式的面板文档

客户端是 GPUI，一套界面两种产物（原生与浏览器版的 wasm，ADR 0015），界面色只准用主题派生的语义 token（ADR 0006），界面上不写死文案。让插件带自己的界面代码进来，三条都守不住：

- **HTML / webview**：原生的网页视图由平台给（wry），浏览器版的 iframe 叠层还没做（rust-unification 附录 B）；插件的页面不认 falcon 的主题，换个主题就是一块突兀的白底；沙箱要单独设计（ADR 0007 为了预览 HTML 已经费了一整套）。
- **WASM 插件**：要在客户端（或服务端）嵌运行时、设计宿主接口（WIT）、管版本兼容，对"在侧栏里显示几个数"来说重得离谱。
- **编进 falcon 的 Rust 插件**：用户要自定义就得重编 falcon，不是插件。

所以插件产出的是**面板文档**（`falcon_proto::PluginView`）：一串固定词汇的块——小标题、文字、提示条、数字卡片、进度条、走势图、键值对、表格、列表、按钮、选项、分隔线。客户端用自己的组件画（`falcon-ui/src/panels/plugin/`），颜色只认语义色调（`default / muted / accent / success / warning / danger`，映射到 Ui token），原生与浏览器版画的是同一份。代价是表现力有上限：插件画不了词汇以外的东西。要新形状就往词汇里加块——老客户端认不出的块不画（`#[serde(other)]`），老插件不写新字段，不用升协议版本。

## 决定二：插件跑在 falcon 后端本机，argv 只来自磁盘上的清单

命令插件是 `<数据目录>/plugins/<id>/` 里的一个文件夹（id 就是目录名），里面一份 `plugin.json` 写明要跑的程序。服务端在**后端本机**起进程，与 meegle（ADR 0010）、cloudflared（ADR 0014）同一个口径：

- **不经 shell**：`command` 是 argv 数组；写成字符串就是一个程序名，不按空格拆（拆了就得管引号，等于实现半个 shell）。相对路径（带分隔符的）相对插件目录。
- **登录环境**：PATH 等取本地 PTY 那份登录环境（`local_base_env`），launchd 拉起的后端照样找得到 Homebrew 里的 `python3` / `jq`。
- **不跟项目走**：不往 SSH 远端推脚本、不在远端跑。焦点项目的信息（id、名字、类型、工作目录、`用户@主机:端口`，不含凭据）随请求交给插件，要看远端的插件自己决定怎么连。往远端推插件意味着要管远端的解释器、POSIX / Windows 两套命令行、部署与版本——为一个还没出现的需求不值得。系统监控看远端是内置插件自己的事（决定五）。

请求同时经两条路交给插件：stdin 上一份完整的 JSON（`PluginRequest`），以及平铺的环境变量（`FALCON_PLUGIN_EVENT`、`FALCON_PARAM_<名字>`、`FALCON_PROJECT_DIR` …）——后者是给 shell 脚本的，它们没有 jq 也能读参数。stdout 是面板文档的 JSON；清单写 `"output": "text"` 的插件 stdout 原样贴成一块等宽文字（`{"command": "uptime", "output": "text"}` 就是一个插件）。

**插件不经 API 安装。** 能往数据目录里放可执行文件的人，本来就能以 falcon 的身份跑任何东西；能登录 falcon 的人只能触发已经装好的插件，请求里能带的只有白名单过的参数名（`[a-z][a-z0-9_]{0,31}`，它们会变成环境变量名）、动作 id 与有长度上限的值。插件 id 来自 URL，不合法的不去拼路径。清单每次请求都重新读，改了 `plugin.json` 立刻生效。

## 决定三：插件的输出不可信，服务端先收一道

- **限时、限量**：缺省 10 秒（清单可设，上限 120 秒），stdout 超过 1 MB 就结束进程，stderr 只留尾巴。Unix 上插件自成一个进程组，超时整组 SIGKILL——插件多半是 shell 脚本，只杀脚本的话它起的 `curl` 攥着管道接着跑。
- **逐块解析**：某一块写错了只把那一块换成一条红色提示（"第 3 块解析失败：…"），别的照画；插件作者对着面板改 JSON，看得到错在哪。表格单元格、数字卡片的值收字符串也收数字（`{"value": 42}` 最自然，为这个让整块报错不值得）。
- **裁剪**（`plugins/view.rs`）：块数、行数、点数、字符串长度都有上限；非有限的数字归零；`openUrl` 只放行 http / https；动作 id 与参数名过白名单。内置插件的文档同样过这一道，客户端只需要信服务端。
- **失败的样子**：退出码非零、超时、输出不是合法 JSON 是 502，`error` 里是给作者看的原话（附 stderr 的最后几行）；停用了 / 清单坏了是 409，客户端据此重新拉列表；没有这个插件 404。客户端画失败时留着上一份文档、顶上一条错误，下一轮照常再试——连不上的那一下不该把面板清空。

## 决定四：交互是"参数 + 动作"，状态在插件那边

面板上能动的只有两种东西：

- **选项**（`select` 块）：取值是面板的**参数**。客户端记着，之后每次请求都带上；换了就立刻重画。回来的文档里 select 的 `value` 又覆盖客户端记的那份——插件说了算（它可以把一个已经不存在的选项改回缺省）。参数只在面板活着的时候有，不持久化。
- **按钮 / 列表行**的动作：`invoke` 回到插件（`event = action`，带动作 id 与 value），回的文档换掉当前面板，可带一条 toast；`confirm` 非空先弹确认框。`openUrl` / `copy` / `refresh` 是客户端自己做的，不回插件。

Docker 插件（决定七）要"管"东西，又补了三样，都还是这两种东西的变体，没有开新的交互模型：

- **`setParam` 动作**：把一个参数改成某个值再重画，客户端自己做。"列表 → 详情 → 返回"就是它：行点进去设 `container=<id>`，「返回」改回空串。详情页不另起一套导航，状态照旧在参数里。
- **文档里的 `params`**：插件改写参数，给没有 select 露着的参数用（详情里的容器被删了，把 `container` 清掉回到列表）。select 的 `value` 盖过客户端是它的特例；两处都说了以 `params` 为准。
- **列表行的菜单**（`menu`）：行尾「⋯」弹出的一组按钮，每项就是一个动作。窄栏里一行放不下三四个按钮，又不该为了停一个容器先点进详情。

插件要记东西就记在 `FALCON_PLUGIN_DATA`（`<数据目录>/plugin-data/<id>/`）。没有给插件开数据库、没有推送通道：每次请求都是无状态地跑一遍进程，插件进程不常驻。toast 只在动作的回应里弹，画面板时带了也不弹——面板两秒重画一次，弹出来就是刷屏。

**重画的节奏归插件**：清单的 `refresh`（秒，≥ 1），文档里的 `refresh` 可以逐次改（≤ 0 = 这次之后别自动重画）。客户端只在面板真的露着时重画——右侧栏切走时视图不卸载（沿用别的面板），但不该还在后台起进程；窗口看不见（最小化、浏览器后台标签页）也停。`scope: "project"` 的插件在侧栏换了焦点项目时重画一次。同一份请求（插件 + 参数 + 焦点项目）同时只跑一个进程：两扇窗口都开着同一个面板时共用一次结果；进程跑在独立的任务上，等结果的请求都断开了也照样跑完、摘掉自己（不然留下一个永远不结束的条目）。动作不合并：两次点击就是两次。

## 决定五：系统监控是内置插件，走同一条路

系统监控不是一块专门的面板，而是 falcon-server 里实现的一个插件（`plugins/sysmon/`），产出的是同一种面板文档。这样插件的词汇在第一天就被一个真实、复杂的面板用满了一遍（数字卡片、三条走势、进度条、表格、选项），词汇缺什么当场就知道（走势图的 `slots` 就是这么加的：攒满之前线从右边长出来，不会刚打开就把两个点拉满整个宽度）。

- **看哪台机器**：面板顶上的「机器」选项——跟随当前项目（SSH 项目看它的远端，其余看本机）、本机、或任一台已保存的 SSH Host。走势按机器分，从"跟随项目"与"选主机"两条路看到的是同一份。
- **本机**用 sysinfo（与客户端经 GPUI 间接依赖的同一版，不多拉一份）。实测的坑：macOS 上进程的 CPU 要到它被看到之后的**第三次**刷新才有值，与间隔无关；第一次采样因此先连刷两遍进程表。Linux 上 sysinfo 缺省给每个进程常开着 `/proc/<pid>/stat`，常驻的服务进程会攥上几百个 fd，关掉（`set_open_files_limit(0)`）。
- **Linux 远端**走一条 POSIX sh 探测脚本（`sysmon/linux.rs`），经 `sh -c` 跑（不依赖远端登录 shell 的语法），一次把 `/proc/stat`、`meminfo`、`loadavg`、`net/dev`、`df -kP`、`ps` 打回来，解析与算差值都在服务端，是纯函数、拿 Ubuntu 与 alpine（busybox）的真实样本做单测。链路是项目自己那条或主机那条（与「浏览远端目录」共用），不另开连接。为什么不在远端跑 sysinfo：远端上唯一的 falcon 二进制是会话守护进程（ADR 0020），给它加采样子命令要把 sysinfo 编进 5 个目标的交叉编译（apple-darwin 要链系统框架，zig 交叉编不顺），还得为此推新守护进程；`/proc` 的格式几十年没变。
- **macOS / Windows 远端暂不支持**，面板上如实说，机器选项照样在。macOS 在 shell 里拿不到累计的 CPU 计数（`top -l 2` 一次要等一秒），Windows 要另写一套 PowerShell。
- **远端的进程表按内存排**：`ps` 的 `%cpu` 是进程一生的平均值，长跑的空闲守护进程会排在刚开始狂转的编译前面；内存是瞬时值，靠得住。本机有两次刷新之间的差，按 CPU 排。
- **采样跟着请求走**，没有后台定时器：面板开着就两秒来一次，没人看就不采。1.5 秒之内的请求共用上一次采样；隔 15 秒没人看，走势与远端的累计计数作废——不然重新打开时第一格是"过去十分钟的平均"。远端第一次探测没有"上一次"，隔 0.6 秒再探一次，第一帧就有 CPU 与网速。

面板上的字是服务端写的（插件文档就是插件自己的内容，客户端只管画），v1 只有中文，文案集中在 `sysmon/render.rs` 一个文件里。

## 决定六：右侧栏的一格就是 `RightPanelId::Plugin(id)`

`RightPanelId` 多一个带 id 的变体，持久化仍是一个字符串：`plugin:<id>`（内置面板照旧是 `git` / `files` …，浏览器版沿用同一个 localStorage 键）。插件被删 / 停用了，读回来照样是它，由面板在插件列表拉回来之后说"没有这个插件"——列表还没拉回来时谁也不知道它在不在，不能在读布局时退回默认。

活动栏上内置四格之后隔一道短线是插件（启用着、清单没坏的那些，内置的在前，其余按 id），命令面板里也有对应的开 / 关。设置多一页「插件」：列出全部插件（含停用的与清单坏的，坏的写明原因、开关不可用）、启用开关（停用的记在 settings 表的 `plugins.disabled`——记停用的而不是启用的，新放进去的插件缺省就开着）、插件目录的路径（服务端给的，后端那台机器上；只给"复制路径"，客户端与后端多半不是同一台）与「重新扫描」。

## 决定七：Docker 也是内置插件，跑那台机器上的 `docker` 命令行

第二个内置插件（`plugins/docker/`）：容器按 compose 项目分组列出，带状态、CPU 与「⋯」菜单（启动 / 停止 / 重启 / 暂停 / 删除、复制 ID 与 `docker exec` 命令）；点进去是详情——占用、端口、挂载、网络、命令、重启策略与最近 200 行日志；另一页是镜像与磁盘占用（`docker system df`），能删镜像、清悬空镜像与构建缓存。机器的选法与系统监控共用（`plugins/machine.rs`），远端同样走项目 / 主机的 SSH 链路。做成内置而不是命令插件的示例，是因为看远端要用 falcon 自己的链路——命令插件只在后端本机跑（决定二），它够不着。

- **只走 `docker` 命令行，不直连 API socket**：远端的 socket 在 SSH 那头要转发；本机的 socket 位置因实现而异（Docker Desktop / OrbStack / colima / rootless 各不相同），CLI 自己认 `docker context`，终端里看到的是哪个守护进程，面板上就是哪个。
- **找 docker**：本机按登录 shell 的 PATH 找，再试 Docker Desktop、OrbStack、Homebrew、Rancher Desktop 的安装位置（launchd 拉起的后端可能连登录环境都没解析出来）；POSIX 远端经 `sh -c` 跑一小段脚本做同样的事——非交互的 SSH exec 拿不到登录 PATH，macOS 上 sshd 只给 `/usr/bin:/bin:/usr/sbin:/sbin`。都找不到、守护进程没开、用户不在 docker 组里，面板上各有各的说法（机器选项留着）。
- **inspect 用模板只取要用的几段**：整份一个容器 4 KB 上下，模板取的 1 KB 左右；`State` 整段取，因为实测 29.x 的 CLI 在 map 上跑模板、缺键就报错，老版本在结构体上跑、`index` 又不认结构体。**不取 `Config.Env`**：环境变量里常有密码，面板上不放。Windows 远端经 PowerShell 5.1 交参数时不转义双引号，模板一进去就碎，那边退回整份 `{{json .}}`。
- **占用不在画面板的路上采**：`docker stats --no-stream` 要等守护进程攒两次采样，实测稳定 2 秒。画列表 / 详情时在旁边起一次，结果留给下一次画（列表三秒一画，数字最多晚一轮）；第一次没有数时写"采样中"、1.5 秒后再画。没人看就不画，也就不采。
- **日志合流**：容器的 stdout 与 stderr 是两条流（经 SSH 也是），`docker logs -t` 带上时间戳，按时间戳合回先后再去掉；docker 的纳秒时间会省掉尾部的 0，排序前补齐。终端控制序列（颜色）去掉。
- **动作的结果**：动作回的是做完之后重画的面板 + 一条 toast；失败时 docker 的原话放进 toast（"container is running: stop the container before removing" 比转述清楚）。删除只给停着的容器，不带 `-f`；清理镜像只清悬空的（`image prune` 不带 `-a`），删除与清理都先确认。动作的 value（容器 id、镜像引用）在服务端过白名单才进 argv，`-f` 一类的东西进不来。

## 决定八：Agent 用量也是内置插件，增量读本机各 Coding Agent 的落盘会话

第三个内置插件（`plugins/tokens/`，id `tokens`）：只读本机已落盘的会话记录，统计 Claude Code（`~/.claude/projects/`）、Codex（`~/.codex/state_*.sqlite` 与 `sessions/`）、Grok CLI（`~/.grok/sessions/`）、Devin CLI（`~/.local/share/devin/`）与 OpenCode（`~/.local/share/opencode/opencode.db`）的 Token 用量、每日走势、按 Agent / 模型分布与高消耗会话排行，点进单段会话可看详情与复制会话 ID / 工作目录。

- **统一输入 Token 口径**：Claude / Devin / OpenCode 的 `input_tokens` 是未命中缓存的新输入，`cache_read` 与 `cache_write` 单独算；而 Codex / Grok 的 `input_tokens` 已经包含了缓存命中部分。解析时统一拆成 `input`（非缓存输入）+ `cache_read` + `cache_write` + `output`，保证各家的 `total` 都等于四项之和，缓存命中率统一按 `cache_read / (input + cache_read + cache_write)` 算。
- **流式与重复节点去重**：Claude Code 流式写盘时同一个 `message.id` 写多行，按 `message.id` 留最后一条并合入 `<session>/subagents/*.jsonl`；Devin 的 `message_nodes` 对同一 `request_id` 写文本与工具调用多条节点，按 `request_id` 去重。
- **按文件 `(mtime_ns, len)` 增量缓存**：JSONL 会话文件攒久了有几百 MB，未变的文件直接复用上次解析出的 `SessionRecord`，3 秒内的重画请求直接共用整份扫描结果。

## 已知的不足

- 插件只在后端本机跑；看远端要插件自己连（或者等内置插件那样的专门实现）。
- 面板词汇有限：没有输入框、没有树、没有可拖动的东西。需要再加块，别给插件开"自定义渲染"的口子。
- 面板参数不持久化：重启客户端后选项回到插件的缺省。
- 系统监控不看 macOS / Windows 远端，远端没有逐进程的 CPU。
- Docker 插件没有"打开终端进容器"（只能复制 `docker exec` 命令）、不跟日志流（三秒重画一次最后 200 行）、不管卷与网络、不做 compose 项目整体的启停；Windows 远端只是按同一套命令行拼了，没在真机上验过。
- 文案只有中文：请求里还没带语言，插件也就没法本地化（加的时候在 `PluginRequest` 里加一个字段，不升协议版本）。
