# 终端尺寸跟「最近操作过的、看得见的那扇窗口」，客户端按 PTY 的尺寸画

一个会话被几个客户端同时开着时（原生客户端 + 浏览器 / 另一台机器），falcon-server 以前给 PTY 的是**所有 Viewer 的最小 cols × 最小 rows**。客户端会给工作区里每扇打开的窗口——包括没在显示的画布——都保持连接并记着最后一次报的格子，于是另一台机器上开着同一个会话、那边窗口窄一点，这边就被压小，直到那边关掉窗口；cols 与 rows 分开取，还能拼出一个谁都不是的尺寸（200×20 加 80×60 得 80×20）。用户看到的是「终端大小随机变化」。

取最小当初是被逼出来的：客户端不知道 PTY 的尺寸，本地网格永远按自己的窗口建，只要 PTY 比某个客户端的窗口大，那个客户端就是按另一个宽度重排程序的输出——全屏程序与 shell 的行编辑整屏折乱（`viewer_arbiter.rs` 顶部注释记的那次「宽屏一直错下去」）。

同类软件的调研（tmux、screen、Zellij、WezTerm、zmx、abduco、mosh、VS Code、terminado、sshx、Warp、Guacamole……）的结论：一个 PTY 在任一时刻只有一个尺寸，没有谁能让同一个程序在两个客户端上各按各的宽度正确排版；各家的差别只在「听谁的」与「对不上的客户端怎么画」。取最小正是 tmux 2.9 之前、Zellij 0.45 之前、terminado、Live Share 的做法，都收到过同一类投诉；tmux 3.1 起默认 `window-size latest`，zmx（同样是 libghostty-vt + 守护进程）用「最后发出真按键的客户端」当 leader。

## 决定一：尺寸跟最近真操作过的、看得见的那扇窗口

`ViewerArbiter::size_owner`：报过格子的 Viewer 里，看得见的优先（都看不见才看全部），取最近一次**真操作**（敲键、粘贴、点击、滚轮——`is_user_input`，终端自动发的 DA / DSR / CPR / 焦点 / OSC 答复不算）的那个；都没操作过时取先连上来的。

- **连上不等于在用**：falcon 给每扇打开的窗口自动建连接，所以 attach 不像 tmux 那样算一次活动；后连上来的只是看，不抢。只有当前没有更早的人时它才接手（zmx 同一口径）。
- **后台不算**：客户端经 WS 的 `visibility` 报这扇窗口在不在屏幕上——不在正在显示的画布上（最大化时只算那一扇）、被总览盖住、助手面板收起或不是当前那段对话、窗口最小化 / 整个被盖住 / 切到别的桌面 / 显示器睡了、浏览器后台标签页，都是看不见。看不见的窗口即使最后敲过键也不定尺寸；它重新看得见时，若仍是最近操作过的那个，尺寸还给它。窗口可见性用 GPUI 的 `observe_window_visibility`（macOS 是 occlusion state，浏览器是 `visibilitychange`）。
- **只看可见、不看前台**：切去别的 App 时窗口还摆在屏幕上，那时把尺寸让给另一台设备会来回整屏重画。
- **都看不见时退回全部**：没人看着时新开的持久会话要靠尺寸接回（wait-size），不退回就一直等不到；这时谁定尺寸没人看得见，代价只是一次重画。锁屏时跑的截图自动化也走这条。
- **持有者走了**交给剩下的人里最近操作过的；所有报过格子的人都走了维持原样（与以前一样，没人看着的会话不为此重画）。

服务端在每次仲裁可能变化后（resize、visibility、input、Viewer 离开）`settle_size`：尺寸变了才 resize PTY、落库；输入触发的换人先 resize 再写这一键，前台程序对这一键的响应已经按新尺寸画。深浅的仲裁不变（照旧跟最近操作的那端，不看可见性）。

宿主机守护进程那一层不用动：holder 在连接之间本来就取「最近有输入或 resize 的那条连接」（设计文档 5.6），现在两层是同一种语义。

## 决定二：生效尺寸推给每扇窗口，不定尺寸的按它建网格

新增 `ServerMessage::Size { cols, rows, owner }`：尺寸或定它的人变了就推给每条连接（`owner` 是「是不是按你报的格子定的」），新连接在回放之前先收一次。两样都没变不推（输入每一键都会来问）。推之前先冲掉合并窗口里的输出：按旧尺寸排的输出在它前面，按新尺寸排的在它后面。

客户端的本地网格（`GridPlan`）：

- `owner` 的那扇（或还不知道服务端尺寸——老服务端、刚连上）照旧按自己窗口放得下的格子建，拖窗当场生效，不等往返；
- 其余的按推来的尺寸建。`size` 必须在**网络线程**上与输出、回放按顺序生效（`Sink` 里就地改网格），换到 UI 线程上再改，紧跟着的回放已经按旧网格解析完了。UI 线程写 fit、网络线程写 server，两边都在同一把锁里改本地终端，免得交错着把旧尺寸写回去。

客户端照旧报自己放得下的格子（`resize`）：它是持久会话接回的信号，也是这扇窗口接手尺寸时要换成的格子。

## 决定三：对不上时先缩放，缩到一半再裁剪跟光标

不定尺寸的窗口里，网格比窗口大就缩小字号放进来（sshx、Guacamole、asciinema 的做法：看得到全貌）；缩到 0.5 倍还放不下就裁掉，平移到刚好看得见光标（光标超出时所在行贴底、所在列贴右，光标隐藏时停左上；tmux 也是跟着光标裁，只是横向居中）。网格比窗口小就画在左上角，网格之外铺窗口底色（`ui.app`，与岛之间的缝同一层），一眼看出那里不属于终端——Zellij#5624 里不加标记的空白被当成了重画 bug。标题栏上有一个显示器图标，悬停说明「尺寸跟着另一扇窗口，在这里输入就改成按这扇窗口的大小」。

自己定尺寸的窗口不标窗口外：拖窗那一帧网格还是旧的，标出来会闪。AI 助手的实时区域不缩放、不竖着平移（外面按行号裁着露，行高变了就对不齐了），只横着跟光标。

## 没做的

- **没做「以本窗口为准」的显式按钮**：在窗口里敲键就是接手。真要加，照 tmux#2594 的教训做成随连接消失的请求，不要把尺寸钉在会话上。
- **没做 resize 合并**：两扇窗口交替打字时全屏程序会被反复整屏重画（tmux 也一样，它靠每个 pane 250ms 的合并压）。目前一键一换，实际用起来不够再加。
- **没留 `smallest` 作可选策略**：两个人要看同一幅完整画面的结对场景，现在的缩放已经能看全；需要时再按会话加开关。
- 老客户端（不认 `size`、不报 `visibility`）连新服务端：当它看得见；它不是定尺寸的那扇、窗口又比 PTY 小时会折乱，与以前取最小前的表现一样。新客户端连老服务端：收不到 `size`，照旧按自己的窗口建网格；`visibility` 被老服务端忽略。
