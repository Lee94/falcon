# 列式工作区：窗口排成可拖的列，tab 栏整条删掉

在这之前，主区是"一条 tab 栏 + 一块内容"：终端 / 文件 / 差异混排在 tab 栏里（`tabOrder` 一维顺序），终端画布把当前项目的终端从左到右摆成列，而文件与差异是**盖在画布上的全屏视图**——想一边看文件一边看终端做不到，只能来回切 tab。列宽也不是用户的东西：一列时占满、多列时 `max(半屏, 40rem)`，写死在 CSS 里。

现在把主区改成一块**工作画布**：窗口（pane）排成从左到右的列，每列从上到下可以叠若干扇，列宽与窗口高度都能拖，抓标题栏能把窗口拖到别的列或另起一列。文件与差异不再是覆盖层，它们就是画布上的窗口。顶部 tab 栏随之删掉——"开着哪些窗口"这件事由画布本身和侧栏的会话行回答，新建入口移到侧栏每个 checkout 行的 ＋。

决定：

1. **排布是两级的 `columns: ColumnLayout[]`**（列 → 窗口），窗口只存一个 key（`t:<sessionId>` / `f:<projectId>:<path>` / `d`，见 `lib/paneKey.ts`）。纯函数层在 `lib/layout.ts`：增删移、与数据源对账、按项目过滤、拖拽落点、像素几何，全部可单测。
2. **排布是全局一份，画之前按当前项目过滤**（`visibleColumns`），不是每个项目各存一份。切项目只是"看不见"，别的项目的列宽与上下关系原样等在那里。
3. **每扇窗口绝对定位，DOM 顺序恒定**（跟着 `tabs` 走，不跟着排布走）。这是硬要求，不是省事：xterm 的画布换过父节点之后渲染尺寸就毁了（见下）。
4. **尺寸只钉一边**：拖列缝钉左边那列的宽度，拖窗口缝钉上面那扇的高度，右边 / 下面的继续自适应。画布本来就横向可滚，不需要此消彼长。双击把手还原成自适应。
5. **文件与差异都是单例预览窗口**，共用一座"查看列"：已经开着另一个查看窗口就落到它下面，否则在当前活动窗口右边另起一列。点另一个文件是同一扇窗口换内容（`replacePane`），不是新开一扇。
6. **新建入口在侧栏**：每个 checkout 行 hover 出 ＋，菜单里是「普通终端 / Claude Code / Codex / Grok」（见 ADR 0013）；行下面列出该项目的会话，点一行把焦点交给那扇窗口，没在画布上的会重新摆一列出来。

## Considered Options

- **保留 tab 栏，只让文件 / 差异也能并排**：tab 栏与画布会变成两套"谁在场"的真相，拖一扇窗口到另一列之后 tab 栏的顺序要怎么跟？删掉它反而简单——画布自己就是那条 strip 的二维版。
- **每个项目一份排布（`Record<projectId, Column[]>`）**：持久化与对账都要多一层，而跨项目的窗口（同一个文件、同一个差异）无处安放。改成全局一份 + 渲染时过滤。
- **列用嵌套 flex（列容器里放窗口）**：最自然的写法，也是第一版的写法。**踩了大坑**：拖窗口换列 = 把终端的 DOM 挪到另一个父节点下，而 xterm 的画布一旦 reparent，渲染尺寸就错——实测整屏空白，一直要等到下一次有输出（敲个回车）才回来；补一帧（`fit()` + 重建字形）能把内容找回来，但字被拉成两倍大（画布位图与 CSS 尺寸的 dpr 比例对不上）。所以改成**自己算坐标、绝对定位**：在 xterm 眼里拖窗口只是一次 resize，而 resize 是它天天在处理的事。
- **用 React Portal 把终端渲进"宿主节点"，再把宿主 appendChild 到列里的插槽**：试过，同一个坑——`appendChild` 就是 reparent。
- **不在场的窗口直接卸载**：`TerminalView` 一卸载就 dispose 适配器并关 WS，挂回来要重连 + replay（4MB ring 之外的历史还会丢）。继续沿用旧画布的做法：挪到 `left:-10000px` 并保持与画布同量级的尺寸——不能用 `transform`（会撑开横向可滚区），也不能 `width:0`（fit 会把 0×0 发给 PTY）。
- **文件窗口允许多开（⌘P 每个文件一扇）**：列很快就会堆满，终端被挤到看不见。改成单例预览，与差异一致。

## 实现要点

- **`syncColumns` 是排布与数据源之间唯一的对账口**：live 之外的 key 一律摘掉（会话结束、文件关了），live 里还没排布的各自接一列到最右。每次会改动 `tabs` / `fileTab` / `diffTab` 的 set 都要过它一遍，漏一次画布上就会留下一扇连着死会话的窗口，或者新开的会话找不到落脚的地方。
- **落点坐标有两套，不能混**：`dropSpot` 是在**可见**列上量出来的（画布画的就是可见列），而 `applyDrop` 改的是全量排布。`resolveSpot` 负责翻译，一律认列 id 与窗口 key，不认下标——当前项目之外的窗口不参与计数，两边的下标只在"当前项目就是全部"时才碰巧一致。
- **`applyDrop` 的两处下标补偿**：摘掉自己之后，同列里排在后面的格子会上移一格；独占的那一列整个消失，它右边的列会左移一格。落回原地（同列同格、独占列拖到自己两侧的缝）返回原数组，调用方据此跳过一次 set——拖着没动也重排一遍会让所有终端白白量一次尺寸。
- **固定列**（窗口标题栏右键的「固定到最右边」）：`ColumnLayout.pinned` 把一列钉在画布最右，新开的终端、查看窗口另起的列、`syncColumns` 补的列一律排在它左边。不变式是**至多一列、且永远是数组的最后一列**，由每个会插列的函数一起维持——落位统一夹到 `pinEdge()` 之前（`insertColumn` 内部就夹，调用方不用记），`pinPane` 是唯一能钉到末尾的口子。拖拽也越不过去：`clampSpot` 同时给拖拽指示线和真正的落位用，只夹一边的话松手之后窗口会跳到指示线左边。列里的窗口关光了，空列被 `compact` 掉，固定跟着消失（不用另外记一份状态）。落盘时带上 `pinned`，读回来只认最后一列的那个——中间冒出来的一律降级成普通列，否则 `pinEdge` 会把它右边整片都封死。
- **列的岛与窗口分两层**：列的圆角、描边、面板底色由底下那层 `.island` 出，窗口浮在上面。窗口自己还要按在列里的位置裁角（`rounded-t-lg` / `rounded-b-lg` / 全圆角）——终端底色是实心矩形，不裁就把岛的圆角盖住了。
- **列宽的自适应公式从 CSS 搬进了 `columnWidth`**（一列占满、多列 `max(半屏, min(全屏, 640))`）：几何现在要在 JS 里算，CSS 的 `max(calc(...), ...)` 拿不到。640 = 40rem，与原来的 CSS 同一个数。
- **把手是绝对定位的窄条，压在缝上**（列缝 `CANVAS_GAP + 8px` 宽，窗口缝 8px 高），`after` 伪元素画那条线：hover 灰、拖动中 primary。拖的过程只改内存里的 `basis`，松手才 `persistLayout()`——每帧同步写 localStorage 会卡。
- **拖拽的监听常驻 window**：pointerdown 只写 ref 不触发重渲，把监听挂在"拖拽中"这个 state 上就永远等不到第一次 pointermove。超过 4px 才算拖（否则是点了下标题栏），拖动期间 `body.pane-dragging` 把 canvas / iframe 的 pointer-events 关掉——终端会把 pointermove 当选区拖拽吃掉，窗口会"粘"在原地。
- **持久化只落终端**：`columns` 里的文件 / 差异窗口与 pending id 都活不过刷新，落盘时过滤掉；恢复时列 id 现生成（它只在一次会话内当 React key 用），再与 `tabs` 对账一遍。认不出形状的排布整条丢掉，退回"每个会话一列"。
- **画布的滚动层没变**：横向滚动仍然自己接管（`lib/termCanvas.ts` 的 `WheelAxisLock`、手势结束后的吸附、把活动列滚进视口），只是列的位置改从 frames 拿。
- **无头截图的坑**：拖完之后在 `deviceScaleFactor: 2` 的无头 Chrome 截图里，终端的字看着被放大了 1.4 倍——那是截图缩放的伪影，同一份代码在 dpr=1 下截图完全正常，页面里读到的 `canvas.width / canvas.getBoundingClientRect().width` 也一直等于 dpr。排查终端渲染问题时不要只信 dpr=2 的截图。
- **这些地方刻意没改**：移动壳（`MobileShell` 仍是全屏单终端 + 抽屉切换）；总览与项目空页仍是盖在画布上的覆盖层（它们没有"并排"的语义）；`tab.*` 那批 i18n key 名保留（文案说的仍是同一件事，改 key 名只会让翻译对不上）。
