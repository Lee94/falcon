# 虚拟项目目录：把多仓库项目的结构注入给 coding agent

多仓库容器（`multi != null` 且非派生行）没有聚合目录：working_dir 只是可选 cwd，留空时会话落在后端进程 cwd（local）或远端 home（ssh），本地容器的文件面板直接 400。在容器会话里启动 Claude Code 等 coding agent 时，agent 既不知道项目由哪些文件夹组成，也没有访问它们的权限。falcon 现在为容器在**数据根下**生成一个「虚拟项目目录」`<falcon 根>/projects/<projectId>/` 作为会话 cwd，批量派生的集中目录也顺手补一份结构清单。实现集中在 `virtualdir.ts`（纯函数：路径 / 模板渲染 / 脚本构造，分层照 paste.ts）。

## 决定一：清单 + 真实路径，不用软链

候选方案是往聚合目录里放成员仓库的软链。实测否决：Claude Code 的 Glob 与 ripgrep 默认都**不跟随软链目录**，从聚合根递归搜索一无所获（显式以链接为根才能搜到）；带沙箱的 agent 还可能按 realpath 把软链出逃当越权拒绝。改为纯清单：

- `AGENTS.md`——成员**绝对路径**清单 + 三条告诫（cwd 下没有代码；递归搜索必须以各成员目录为根；各成员是独立仓库）。跨 agent 通用（AGENTS.md 是 Codex / Cursor 等都认的约定）。
- `CLAUDE.md`——全文精确为 `@AGENTS.md`（Claude Code 的 memory import）。不复制全文：Claude Code 两个文件都认，复制会加载出双份。
- `.claude/settings.json`——`permissions.additionalDirectories` 指向成员绝对路径，Claude Code 的越 cwd 授权。不认这个文件的 agent 退化为逐次授权，AGENTS.md 指引仍有效——整个功能是渐进增强。

集中目录版只有前两个文件（成员用 `./<basename>/` 相对路径）：成员都在 cwd 内，不需要越界授权，从 cwd 递归搜索本来就能命中。

内容全部模板确定性渲染，**不用 LLM**：路径与成员是 falcon 手里的事实，模板即时、零成本、永不编造；语义描述靠 agent 自己去读成员仓库里的文档（Claude Code 读到子目录文件时会按需加载那边的 CLAUDE.md）。

## 决定二：目录名用 projectId，路径不落库

`<falcon 根>/projects/<projectId>/`，不用 nameSlug：两个容器同名会撞目录、互相覆盖清单且删除时无法归属；任何含 name 的方案（含 `slug-id8`）在改名后都孤儿化旧目录、旧 settings.json 还在放行旧成员。UUID 的代价是终端提示符不好看——AGENTS.md 首段写明项目名缓解，会话 UI 本来显示项目名。

路径因此是 `f(root, projectId)` 纯函数可算：**零 DB / shared 改动**，删除时手里有 id 就能复算。放 falcon 根下还有两重结构收益：清理属自有目录（paste/ 先例，不违反「remove.ts 是唯一删用户可见路径的地方」）；与派生集中目录 / 仓库同级路径在构造上零冲突（`vetoMultiRemoval` 的包围盒与 otherDirs 断言完全不受影响）。Windows 路径预算 ~90 ≪ 200。

## 决定三：先写后指，attach 每次重写

cwd 语义：working_dir 显式设置则尊重、不生成；留空才落虚拟目录。materialize 成功才把路径交给 opts.cwd，失败 catch 回退 `undefined`（= 现状行为）——创建与接回（`ensureAttached` 同走 `attachBackend`）都不能被它挡住，否则宿主离线时容器会话一个都开不出来。

attach 路径**不走缓存、每次覆盖重写**（POSIX 一次往返，Windows 远端逐文件）：成员/名字编辑后新会话必然拿到新清单；用户误删目录后接回自愈——不重写的话 durable 的 `--default-cwd` 与非 durable 的 `cd` 都会指向不存在的目录。写入天然幂等（确定性内容覆盖写）。进程内缓存只给文件面板这类只读路径用（`fileHostFor` 对无 working_dir 的容器返回虚拟目录为根，顺手修掉了本地容器文件面板 400 的洞）。

已知代价：Claude Code 把「always allow」类项目级授权也写进 `.claude/settings.json`，会被下次 attach 覆盖掉。v1 接受（文件头注明由 falcon 维护）；将来可改读-改-写只合并 `additionalDirectories`。

## 决定四：删除守护式、绝不递归

两条删除路径，全部**非递归**、只认固定文件名：

- **容器删除**（DELETE 级联里的 else 分支，manager.removeVirtualDir）：只删三个固定文件 + rmdir `.claude` + rmdir 目录。虚拟目录是会话 cwd，agent/用户可能落了别的文件——非空整目录保留 + warning 带路径。stdout 协议 `gone|left`；Windows 用 `[IO.File]::Delete` / `[IO.Directory]::Delete($p,$false)`（字面量、非递归，Remove-Item 的通配陷阱见 ADR 0002）。
- **集中目录清单**（cleanupMultiWorktree 里、空目录删除之前，住在 remove.ts）：守护式——AGENTS.md 首行要含 `generated by falcon` 标记、CLAUDE.md 全文 trim 后要精确等于 `@AGENTS.md` 才删。用户整文件改写/替换的视为用户文件，保留 → rmdir 因非空失败 → 既有 warning 带路径，方向安全（与 vetoMultiRemoval 同一态度：比对不过宁可不删）。**标记式守护的精确语义**：在文件尾部追加、首行标记还在的内容仍会随清理消失（文件头已写明会被清理）；AGENTS.md 不做全文比对是刻意的——模板措辞跨版本会变，全文比对会让升级后的每个旧派生行永远删不干净。CLAUDE.md 内容是常量才用全文比对。

派生时的清单**写失败不回滚**、只记日志：全有或全无护的是 worktree——建错了要付回滚代价的东西；清单是可再生的引导文件，为它逆序 remove N 棵刚建好的树得不偿失。集中目录必然是本请求新建的（ADR 0003 决定二），首写无覆盖风险。

PUT 编辑容器后的刷新是 fire-and-forget：宿主离线不能挡编辑，失败下次 attach 自愈。

## Windows 写入的编码取舍

远端内容走 `execWithInput` + stdin base64 + `[IO.File]::WriteAllBytes`（paste.ts 同套路），不用 `Set-Content`：默认编码是 ANSI 代码页（简体中文机器写出 GBK），`-Encoding UTF8` 又带 BOM——BOM 会弄坏 `.claude/settings.json` 的 JSON 解析；内容内联进 `-EncodedCommand` 还可能顶穿 cmd.exe 的 8191 字符上限。本地（含 Windows 本地）一律 node:fs，整类问题归零。

## 验证

纯函数层全套单测（virtualdir.test.ts：路径拼接、模板锚点与特殊字符成员路径、settings JSON round-trip、写入/删除脚本形态、删除脚本无任何递归、守护条件）。macOS 本地经 REST 跑通端到端：

- 容器创建 → 文件面板首开顺手 materialize 三文件（内容含中文项目名与含空格路径均正确）。
- PUT 改名/删成员 → AGENTS.md 标题与成员、settings.json 的 additionalDirectories 都在 1s 内刷新（fire-and-forget）。
- 会话：durable 会话的 `zellij attach` 带 `--default-cwd <数据根>/projects/<id>`，pane shell 的实际 cwd（lsof 取证）就是虚拟目录；容器显式设置 working_dir 时 `--default-cwd` 用它、不生成虚拟目录。（顺带复证了数据目录长路径撞 unix socket 上限会让 durable 会话当场 exited——e2e 数据目录必须短路径。）
- 批量派生 → 集中目录两文件（无 settings.json），成员相对路径 + 源仓库根正确。
- 删派生行 → 清单被守护删除、集中目录 rmdir 消失、**零 warning**、成员仓库纹丝不动；把 AGENTS.md 整文件改写再删 → 文件保留、集中目录保留 + warning 带路径（追加不动首行的场景确认会随清理消失，与上面的语义一致）。
- 删容器 → 虚拟目录彻底消失；塞入杂文件再删 → 三个清单文件被删、目录保留 + 「虚拟项目目录未删除（内有其他文件）」warning。

**未验证**：SSH 远端（POSIX 与 Windows）全部路径、Windows 本地、宿主离线时的降级路径（materialize 失败回退 / PUT 不被挡，仅代码推演）、在虚拟目录真启动 Claude Code 验证 additionalDirectories 生效（机制本身已在 falcon 仓库外单独实测过：软链不被 Glob/rg 跟随、additionalDirectories 放行越 cwd 读取）。
